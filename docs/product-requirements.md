# **2. 产品背景与核心判断**

传统录音工具的价值正在降低，因为手机系统、会议软件、办公协作平台和 AI 转写工具已经提供了基础录音、转写、纪要能力。真正有机会的不是“录音”，而是把工作沟通转化为可持续调用的工作资产。

本产品应避免定位为普通录音 App，而应定位为 AI 工作记忆系统：它记录的不是声音本身，而是工作过程、关系、承诺、判断、风险和复盘。

|   |   |   |
|---|---|---|
|**错误定位**|**问题**|**推荐定位**|
|AI 录音助手|同质化严重，用户容易与手机录音、讯飞、飞书、钉钉比较。|AI 工作记录助手|
|会议纪要工具|只能解决单次会议总结，价值链太短。|工作过程沉淀系统|
|转写工具|付费点弱，模型/转写成本高。|工作记忆与报告生成工具|
|硬件录音笔|供应链、成本、渠道和竞品压力大。|先做软件验证，后期再探索硬件入口|

## **2.1 产品机会**

· 销售、项目、管理、创意四个方向都存在“沟通后整理成本高”的问题。

· 用户真正痛苦的不是忘记录音，而是忘记客户需求、会议承诺、项目风险、创意决策和复盘依据。

· 垂直场景模板比通用总结更有价值，能直接生成用户要交付的日报、周报、客户记录、项目复盘和创意资产。

· 个人用户可以先免费验证，小团队是后续商业化和增长的核心。

# **3. 产品定位与目标**

|   |   |
|---|---|
|**维度**|**定义**|
|产品定位|面向个人和小团队的 AI 工作记录与工作记忆系统。|
|目标用户|销售、项目经理、团队管理者、创意/设计/视频/品牌团队成员。|
|核心价值|减少手动记录、自动生成工作成果、沉淀长期记忆、支持随时检索与复盘。|
|使用入口|录音、上传音频、手动文本输入。|

|长期形态|个人工作秘书 + 小团队工作记忆平台 + 可选硬件记录入口。|

|   |
|---|
|**北极星指标**<br><br>用户每周主动生成并保存的“有效工作记录”数量。有效工作记录指：完成转写、被 AI 结构化、进入某个档案或报告，并在之后被搜索、复用、导出或问答调用。|

## **3.2 产品目标分层**

|   |   |   |
|---|---|---|
|**阶段**|**目标**|**判断标准**|
|MVP|验证用户是否愿意把真实工作沟通交给产品整理。|10-30 个种子用户连续使用 2 周；每周平均 3 条以上有效记录。|
|V1|形成稳定的记录 → 整理 → 归档 → 搜索/问答闭环。|用户能用产品生成日报/周报、客户记录或项目复盘。|
|V2|进入小团队场景，支持团队看板、共享档案和权限管理。|团队版留存和付费意愿明确。|
|V3|探索硬件入口、企业集成、私有化部署。|已有稳定高频场景和付费基础。|

# **4. 用户画像与核心场景**

根据当前设定，产品不是面向所有职场人，而是优先面向“工作沟通多、记录负担重、需要复盘/追踪/报告”的用户。

|   |   |   |   |
|---|---|---|---|
|**用户类型**|**典型痛点**|**产品价值**|**优先级**|
|销售/商务|拜访后懒得写记录；客户需求、预算、异议、下次跟进容易丢。|自动生成客户画像、拜访记录、跟进建议、销售日报。|高|
|项目经理|会议多、任务散、责任人和截止时间不清、需求变更难追踪。|自动沉淀会议纪要、项目状态、风险、周报、复盘。|高|
|团队管理者|1on1 沟通缺少连续记录，成员状态和承诺事项难追踪。|轻量沟通备忘、成员状态记录、下次沟通提醒。|中|
|创意/设计/视频团队|讨论中灵感、否定原因、客户反馈和修改意见容易散落。|沉淀创意关键词、方案方向、反馈、分镜脚本、知识库。|高|

## **4.1 核心使用场景**

|   |   |   |
|---|---|---|
|**场景**|**触发时机**|**用户想得到的结果**|
|工作沟通后|客户拜访、项目会议、创意讨论、1on1 后。|一份结构化记录 + 下一步建议。|
|写日报/周报前|下班前、周五、项目例会前。|自动汇总本日/本周工作。|
|复盘前|项目交付后、客户流失后、团队问题出现后。|基于历史记录生成复盘和问题分析。|
|再次沟通前|下次见客户、下次开项目会、下次 1on1 前。|快速回顾上次聊了什么、谁承诺了什么、还有哪些风险。|
|灵感整理时|创意讨论、拍摄方案、广告策划、AI 设计流程中。|将零散想法沉淀为可复用的关键词库/方案库。|

# **5. 产品形态与信息架构**

## **5.1 产品形态建议**

|   |   |   |
|---|---|---|

|硬件|V3 再做|需要供应链、成本控制、售后和渠道，先用软件验证需求。|

# **7. 页面设计方案**

页面设计建议采用“极简卡片式 + 工作台结构”。不要一开始做复杂系统后台，而是把核心动作放在首页：开始记录、查看最近记录、生成报告、进入记忆库。

## **7.1 全局导航**

|   |   |   |
|---|---|---|
|**导航项**|**说明**|**MVP 是否需要**|
|记录|开始录音、上传音频、文本输入。|必须|
|记忆库|客户、项目、团队沟通、创意、报告沉淀。|必须|
|AI 问答|基于历史记录提问。|必须|
|报告|日报、周报、复盘、跟进报告。|建议|
|我的/设置|隐私、本地存储、导出、模板管理。|必须|

# **10. AI 能力与输出结构**

## **10.1 AI 处理链路**

|   |
|---|
|音频/文本输入  <br>  ↓  <br>ASR 转写  <br>  ↓  <br>说话人区分 + 时间戳  <br>  ↓  <br>场景识别 / 用户选择模板  <br>  ↓  <br>信息抽取：人物、主题、问题、风险、承诺、需求、反馈  <br>  ↓  <br>结构化生成：按模板输出 JSON  <br>  ↓  <br>档案更新建议：客户/项目/团队/创意库  <br>  ↓  <br>报告生成：日报/周报/复盘/跟进建议  <br>  ↓  <br>检索增强问答：基于历史记录回答|

## **10.2 AI 输出原则**

· 先结构化，再生成自然语言。不要只让模型输出一段漂亮总结。

· 每个结论都尽量保留来源：来自哪段录音、哪位说话人、哪个时间点。

· 重要字段允许用户编辑，编辑后的内容优先进入记忆库。

· 对不确定内容标注置信度，例如“疑似预算”“未明确责任人”。

· 禁止 AI 编造未出现的客户需求、承诺、预算、风险或员工状态。

## **10.3 输出 JSON Schema 总体结构**

|   |
|---|
|{  <br>  "record_id": "string",  <br>  "scene_type": "sales \| project \| management \| creative \| free",  <br>  "source_type": "recording \| upload \| text",  <br>  "created_at": "datetime",  <br>  "participants": [],  <br>  "transcript": {  <br>    "language": "zh-CN",  <br>    "speaker_segments": []  <br>  },  <br>  "summary": {  <br>    "one_sentence": "",  <br>    "key_points": [],  <br>    "keywords": []  <br>  },  <br>  "structured_result": {},  <br>  "risks": [],  <br>  "suggestions": [],  <br>  "report_text": "",  <br>  "memory_updates": [],  <br>  "confidence": {  <br>    "overall": 0.0,  <br>    "low_confidence_fields": []  <br>  }  <br>}|

# **11. 数据结构与本地存储设计**

用户倾向本地存储，因此 MVP 建议采用“本地优先”的数据策略：核心记录默认保存在用户设备或本地数据库中；需要跨设备同步时再引导用户开启云端同步。

|   |   |   |
|---|---|---|
|**数据对象**|**关键字段**|**说明**|
|Record 记录|record_id、title、scene_type、created_at、source_path、status|一次录音/上传/文本输入。|
|Transcript 转写|record_id、segments、speaker、start_time、end_time、text|原始可追溯文本。|

# **16. 风险清单与应对方案**

|   |   |   |
|---|---|---|
|**风险**|**表现**|**应对**|
|同质化|用户认为只是录音转写。|首页和传播强调“工作记忆、报告、复盘、档案”，弱化录音。|

|管理场景敏感|被理解成监控员工。|第一版只做个人备忘，避免绩效评分和监控表述。|
|场景过多|四个方向都做导致体验分散。|底层通用，模板轻量；优先打磨销售、项目、创意。|

# **18. 你可能没有想到的补充项**

|   |   |   |
|---|---|---|
|**补充项**|**为什么重要**|**建议做法**|
|待整理机制|很多用户录完就不看，产品价值会丢失。|首页显示未保存、未归档、未生成报告的记录。|
|置信度标记|AI 总结容易让用户误以为完全准确。|对预算、承诺、风险等关键字段标低/中/高置信度。|
|来源追溯|工作记录可能用于正式汇报，必须能查来源。|关键结论绑定原文片段和时间戳。|
|模板自定义|不同团队字段不同。|V1 支持用户增删字段。|
|命名与归档|记录多了之后难找。|AI 自动生成标题、标签、关联对象。|
|回收站|用户误删工作记录会很严重。|删除先进入回收站，保留 7/30 天。|
|敏感记录模式|1on1、客户合同、内部会议都可能敏感。|敏感记录默认不进入周报、不被团队共享。|
|失败重试|转写或总结失败会影响信任。|显示失败原因，允许重新生成或换模板。|
|样例数据|空产品很难让用户理解价值。|内置销售、项目、创意 3 个样例记录。|
|导入旧资料|用户已有微信、飞书、会议纪要。|后续支持粘贴文本或导入已有纪要沉淀到记忆库。|
|反馈闭环|AI 质量需要持续调。|每张结果卡提供“准确/不准确/缺失字段”反馈。|

## **19.6 产品落地建议**

· 第一步先做 Web/H5 原型，不急着开发原生 App。

· 第二步找 10 个真实用户，每人至少提供 3 条真实或半真实工作记录。

· 第三步只打磨 3 个核心输出：销售画像、项目周报、创意复盘。

· 第四步确认用户最愿意付费的结果，不要只验证转写。

· 第五步再决定是否扩展团队版、插件或硬件。

# **结语**

|   |
|---|
|**最终建议**<br><br>本产品应该从“录音工具”转向“AI 工作记忆系统”。第一版要跑通最小闭环：记录 → 转写 → 场景化结构整理 → 保存到记忆库 → 搜索/问答 → 生成报告。只要这个闭环被真实用户反复使用，后续销售、项目、创意和团队版本才有继续扩展的价值。|
